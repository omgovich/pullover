# GitHub Review Inbox — дизайн

**Дата:** 2026-08-31
**Статус:** утверждён

## 1. Концепция

Menu-bar приложение для macOS (Electron + React) — «умный инбокс» для code review.

Центральная идея — **«мяч на моей стороне»**: приложение показывает только те PRы,
которые прямо сейчас требуют действия пользователя, и прячет те, где он ждёт других.
Клик по PR открывает его на github.com — ревью происходит в браузере.
Бейдж на иконке в меню-баре показывает число PRов, требующих внимания.

## 2. Категории («чей мяч»)

Каждый открытый PR из отслеживаемых репозиториев классифицируется ровно в одну
категорию. Категории перечислены в порядке приоритета — если PR подходит под
несколько, побеждает верхняя.

### Требуют внимания (считаются в бейдже)

1. **Нужно ревью** — пользователь в reviewers (лично или через команду) и ещё не
   оставил ни ревью, ни камента в этом PR.
2. **Новые ответы тебе** — существует неразрешённый (not resolved) тред, в котором
   пользователь участвовал, и последний коммент в нём не его (кто-то ответил после
   его камента). Resolved-треды игнорируются полностью и ни на что не влияют.
3. **Re-review** — пользователь оставил ревью (changes requested или каменты),
   после чего автор запушил новые коммиты или заново запросил ревью
   (re-request review).
4. **Твои PRы — нужна реакция** (пользователь — автор):
   - получен changes requested;
   - есть неразрешённые треды, где последний коммент не его;
   - все требуемые апрувы собраны — можно мержить;
   - CI упал (statusCheckRollup = FAILURE).
5. **Упоминания** — пользователя @упомянули в PR, где он не ревьюер и не автор.

### Waiting (свёрнутая секция, не считается в бейдже)

- Пользователь оставил каменты/changes requested — автор ещё не ответил и не
  запушил новых коммитов.
- Собственные PRы, где он ждёт ревьюеров (ревью запрошено, реакции нет).
- Вручную снузнутые PRы. Варианты snooze: до ответа в моих тредах, до новых
  коммитов, на N часов.

### Исчезает из инбокса

PR пропадает совсем, когда он смержен, закрыт, переведён в draft
или ревью-запрос с пользователя снят (и других причин показа нет).

## 3. Данные и архитектура

### Авторизация

- OAuth Device Flow (регистрируется собственный OAuth App на github.com).
- Токен хранится в macOS Keychain через Electron `safeStorage`.
- Только github.com; Enterprise вне скоупа.

### Источник данных

- GitHub GraphQL API v4.
- Поллинг: по умолчанию раз в **5 минут**, интервал настраивается.
- Кнопка **ручного рефреша** в UI (плюс автоматический рефреш при открытии окна,
  если данные старше минуты).
- Два слоя запросов за цикл:
  1. `search` по выбранным репозиториям: `review-requested:@me`, `author:@me`,
     `involves:@me`, `mentions:@me` (open PRs).
  2. Для каждого найденного PR — `reviewThreads` (авторы каментов, `isResolved`,
     последний коммент), `reviews` (state, автор, дата), `commits` (даты пушей),
     `reviewRequests`, `statusCheckRollup`, размер диффа (`additions`/`deletions`).
- Ошибки сети/rate limit: показываем время последнего успешного обновления и
  ненавязчивый индикатор ошибки, ретраим на следующем цикле.

### Классификатор

Чистая функция: `(данные PR, myLogin, локальное состояние) → категория`.
Это ядро приложения; покрывается юнит-тестами на все категории и граничные случаи
(resolved-треды игнорируются, приоритет категорий, снузы, команды-ревьюеры).

### Локальное состояние (electron-store)

- Список отслеживаемых репозиториев (добавление через поиск по имени `owner/repo`).
- Снузы (тип и срок действия по каждому PR).
- Отметки «просмотрено» — для подсветки нового с последнего визита.
- Настройки: интервал поллинга, уведомления вкл/выкл.

### Процессы Electron

- **Main:** трей-иконка и бейдж, поллер, GraphQL-клиент, OAuth-флоу, хранилище,
  нативные уведомления.
- **Renderer:** React-дашборд.
- Связь — typed IPC (события «данные обновились», команды «рефреш», «snooze»,
  «открыть PR»).

## 4. UI

- **Стек:** React + [Reshaped](https://reshaped.so) UI Kit + TypeScript.
- Иконка в меню-баре со счётчиком. Клик — попап-окно с дашбордом.
- Хедер окна: кнопка ручного рефреша, время последнего обновления, настройки.
- Список секциями в порядке приоритета:
  Нужно ревью → Новые ответы тебе → Re-review → Твои PRы → Упоминания →
  Waiting (свёрнута по умолчанию).
- **Карточка PR:** репозиторий, номер, заголовок, автор (аватар), возраст,
  причина попадания в категорию («2 новых ответа в твоих тредах»),
  статус CI, размер диффа (+/−).
- Действия на карточке: открыть в браузере (клик по карточке), snooze,
  «пометить просмотренным».
- Нативные macOS-уведомления — опционально, по умолчанию выключены:
  новый PR на ревью, новый ответ в твоём треде.

## 5. Вне скоупа v1

- Просмотр диффа внутри приложения.
- Ответы на каменты, approve/request changes из приложения.
- GitHub Enterprise / кастомные хосты.
- Windows и Linux.
- Несколько GitHub-аккаунтов.
